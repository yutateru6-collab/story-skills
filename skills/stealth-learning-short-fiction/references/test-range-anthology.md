# Test-Range Anthology Planning

Use this workflow when the user wants an entire test range, example bank, lesson set, or worksheet collection turned into entertaining short stories.

## Goal

Cover the required target sentences without making any single story feel overloaded.

The output should feel like a short-story anthology whose hidden constraint happens to be complete test-range coverage.

## 1. Extract before inventing

Read the authoritative test/source material first.

Build a coverage ledger with one row per exact target sentence:

| ID | Source | Exact English | Japanese | Grammar/meaning supported by source | Story assignment | Status |
|---|---|---|---|---|---|---|
| T01 | Test 3-2 | ... | ... | ... | Story B | planned |

Do not reconstruct sentences from memory if the source is available.

## 2. Separate target inventory from story design

First establish what must be covered.

Only then design stories.

This prevents the model from inventing a fun premise first and silently omitting inconvenient test sentences.

## 3. Group by semantic compatibility, not merely source order

Sentences may be grouped together when they can naturally belong to the same incident.

Examples of compatible clusters:

- sports action + sports history + future sports plan
- social media obligation + accidental message + regret/speculation
- travel schedule + prior experience + future arrangement
- everyday routine + current action + interruption

Do not group sentences merely because they occur next to each other on the test if their situations clash.

## 4. Story density

Default target density:

- Micro story: 1–2 exact targets
- Standard story: 2–4 exact targets
- Extended story: 3–5 exact targets

If a test contains ten sentences, three or four short stories are usually preferable to one story containing all ten.

Treat these as defaults, not mathematical requirements.

## 5. Genre distribution

For a multi-story set, create a genre plan before drafting.

Example internal plan:

| Story | Genre | Emotional promise | Target IDs | Ending shape |
|---|---|---|---|---|
| A | sports | pressure + recognition | T01,T02,T03 | renewed decision |
| B | school comedy | embarrassment | T04,T05 | punchline |
| C | horror | creeping dread | T06,T07 | chilling implication |
| D | romance | small vulnerability | T08,T09,T10 | quiet shift |

Do not use this exact sequence by default. It is an illustration of variation.

## 6. Avoid genre monoculture

Across an anthology, avoid defaulting repeatedly to:

- isekai
- school romance
- wrong-message plots
- supernatural mystery
- mentor/student lecture scenes

Use the target semantics to create varied situations.

## 7. Give every story an independent premise

Each story should be pitchable without mentioning English or grammar.

Weak pitch:

> A story that teaches present perfect.

Strong pitch:

> A bench player planning to quit discovers his rival has quietly been arriving before him every morning.

If the pitch contains a grammar label, rewrite the premise.

## 8. Coverage is internal, not reader-facing

Do not automatically print:

- coverage percentages
- grammar labels
- target IDs
- audit tables
- PASS/FAIL reports

Those are production controls. Reader-facing output should remain fiction unless the user asks for teaching notes.

## 9. Exact coverage audit

After all stories are drafted:

1. re-read the authoritative source
2. compare the source inventory with the anthology ledger
3. verify every required target is assigned
4. verify each assigned target appears exactly
5. verify the correct Japanese translation follows it
6. identify duplicates and omissions
7. verify no extra invented sentence is being presented as a test target

Coverage is complete only when every required target is accounted for.

## 10. Story quality still outranks packing efficiency

If one remaining sentence makes a story noticeably worse, do not force it into that story. Create another micro story or reassign it.

A four-story anthology with strong stories is better than a three-story anthology with one obvious worksheet disguised as fiction.

## 11. Reuse for later recall practice

Keep the internal sentence-to-story mapping so later practice can refer back to a memorable scene.

Possible later modes when requested:

- exact test blank-fill
- Japanese-to-English recall
- "which story was this sentence from?"
- scene cue -> reconstruct sentence
- shuffled sentence recall

Do not append these modes automatically to the fiction.
